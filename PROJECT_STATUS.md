## Описание проекта

Тактическая игра "Морской Бой" в стиле WeGO (Write-Go) с детальной системой повреждений кораблей, базой данных кораблей и редактором отсеков.

---

## Реализованные функции

### 1. Боевая система

#### Фазы боя
- **Движение** - перемещение кораблей по гексагональной сетке
- **Планирование** - выбор целей для стрельбы
- **Выполнение** - расчёт попаданий с анимацией
- **Результаты** - статистика и переход к следующему ходу

#### Гексагональная сетка
- Размер: 42×42 гексов
- Каждый гекс = 5 метров
- Размер гекса: 15 пикселей (HEX_SIZE = 15)
- Отображение траекторий движения кораблей
- Визуализация дальности стрельбы
- Карта помещается целиком на экране 1920×1080 без скроллинга

#### Система стрельбы
- Расчёт вероятности попадания на основе точности корабля
- Пробитие брони с учётом типа снаряда и толщины брони
- Распределение урона по отсекам
- Отслеживание попаданий (hitMarkers) с указанием:
  - ID корабля и отсека
  - Номер хода
  - Нанесённый урон

### 2. Система повреждений

#### Типы отсеков
1. **Мостик** (bridge) - жёлтый цвет (#eab308)
2. **Система управления и обнаружения** (control_system) - жёлтый цвет (#eab308)
   - КДП, БИУС, Дальномер, Радар, Гидролокатор
3. **Вооружение** (weaponry) - тёмно-красный цвет (#7f1d1d)
   - ГК, вспомогательный калибр, торпедные аппараты, зенитки
4. **ГЭУ** (propulsion) - тёмно-синий цвет (#1e3a8a)
   - Котлы, турбины
5. **Руль** (rudder) - тёмно-синий цвет (#1e3a8a)
6. **Винты** (propellers) - тёмно-синий цвет (#1e3a8a)
7. **Боезапас** (ammunition) - тёмно-коричневый цвет (#78350f)
8. **Остальные отсеки** (other) - тёмно-зелёный цвет (#14532d)
   - Жилые и вспомогательные отсеки, включая топливо

**Примечание:** Тип "Топливо" удалён. Топливо теперь считается по общему повреждению корабля.

#### Статусы отсеков
- **Целый** (intact) - цвет по типу отсека
- **Повреждённый** (damaged) - светло-серый (#d1d5db)
- **Затопленный** (flooded) - цвет по типу + иконка 💧
- **Пожар** (on_fire) - цвет по типу + иконка 🔥
- **Уничтоженный** (destroyed) - тёмно-серый (#374151)

#### Механики повреждений
- **Пожары** - распространяются между отсеками, усиливаются в отсеках с топливом
- **Затопления** - распространяются с учётом водонепроницаемости переборок
- **Детонация боезапаса** - риск при повреждении отсеков с боезапасом
- **Потеря плавучести** - при критическом затоплении
- **Потеря боеспособности** - при уничтожении ключевых систем

#### Влияние повреждений на характеристики
- **Скорость** - зависит от состояния ГЭУ, руля, винтов
- **Управляемость** - зависит от мостика, руля
- **Огонь ГК** - зависит от вооружения и систем управления
- **ПВО** - зависит от зенитного вооружения
- **Обнаружение** - зависит от радаров и систем управления
- **Плавучесть** - зависит от общего затопления

### 7. Стратегическая карта Тихого океана

#### Основные возможности
- **Размер карты**: 9703 × 7767 пикселей
- **Viewport culling** - отрисовка только видимой области для оптимизации производительности
- **Canvas-based рендеринг** для высокой скорости отрисовки
- **Pan & Zoom** - перетаскивание мышью и масштабирование колесом мыши
- **Тайловая система** - разбиение карты на 42 части (6 рядов × 7 колонок)
- **Размеры тайлов**:
  - Стандартные тайлы (00-05, 07-12, 14-19, 21-26, 28-33): 1500 × 1500 пикселей
  - Тайлы последнего столбца (06, 13, 20, 27, 34): 703 × 1500 пикселей
  - Тайлы последнего ряда (35-40): 1500 × 267 пикселей
  - Тайл 41 (правый нижний угол): 703 × 267 пикселей
- **Гексагональная сетка** - полупрозрачная сетка поверх карты
  - Оригинальный гекс: 53 пикселя высота × 43 пикселя ширина
  - Новый гекс (в 2 раза меньше): 26.5 пикселя высота × 21.5 пикселя ширина
  - Сетка покрывает всю карту (9703 × 7767 пикселей)
  - Pointy-top ориентация гексов с смещением нечётных рядов
  - **Настраиваемая прозрачность** - от 0% до 100% (по умолчанию 30%)
  - Viewport culling для оптимизации (отрисовка только видимых гексов)
- **Кэширование изображений** - загруженные тайлы кэшируются для производительности
- **Интерактивные элементы** - 15 объектов на карте (города, базы, корабли)
  - 🏙️ Города: Токио, Гонолулу, Сидней, Анкоридж, Сан-Франциско, Манила
  - ⚓ Военно-морские базы: Йокосука, Субик-Бей, Мидуэй, Перл-Харбор, Дарвин, Датч-Харбор, Сан-Диего
  - 🚢 Корабли: Линкор Ямато, Авианосец Энтерпрайз

#### Управление картой
- **Обычный курсор** - `cursor: default` на всей области карты
- **Перемещение** - зажатие ЛКМ + движение мыши (порог срабатывания 4 пикселя)
- **Клик по элементу** - короткий клик (без перемещения) открывает модальное окно с информацией
- **Масштабирование** - колесо мыши или слайдер в верхней панели
- **Быстрые масштабы** - кнопки 50%, 100%, 150%, 200%

#### Модальное окно элемента
- Иконка элемента
- Название и тип (город/база/корабль)
- Описание
- Координаты X и Y
- Кнопка закрытия

#### Редактор стратегической карты (StrategicMapEditor.tsx)
- Загрузка 42 изображений (00-41) для тайлов карты
- Drag & Drop поддержка для загрузки файлов непосредственно на тайлы
- Автоматическое определение позиции тайла по номеру в имени файла
- Визуальное отображение загруженных тайлов в сетке 7×6 с правильными размерами
- **Автоматическое сохранение в IndexedDB** при каждом изменении (поддержка до нескольких ГБ)
- Автоматическая миграция из localStorage при первом запуске
- **Экспорт данных** в JSON файл для резервного копирования
- **Импорт данных** из JSON файла для восстановления
- **Загрузка образца гекса** для отрисовки сетки
  - Автоматическое удаление белого фона (порог 240)
  - Превью с текущей прозрачностью
- **Шкала прозрачности границ сетки**
  - Слайдер от 0% до 100% с шагом 5%
  - Быстрые кнопки: 0%, 10%, 20%, 30%, 50%, 70%, 100%
  - Автосохранение при каждом изменении
  - Значение по умолчанию: 30%
- Индикация статуса загрузки (зелёная рамка для загруженных тайлов)
- Отображение размеров каждого тайла в интерфейсе
- Утилиты для работы с IndexedDB (`src/utils/indexedDB.ts`)
- Кнопки управления: загрузить, сохранить, экспортировать, импортировать, очистить

#### Технические детали

- Динамическое масштабирование (от 10% до 200%)

## Отладка системы боя (последнее обновление)

### Исправлена проблема с замыканиями React

**Проблема**: Функция `executePhase` использовала `playerShotTargets` из замыкания, но из-за асинхронности React state это было старое значение (пустой массив).

**Решение**: Добавлен `useRef` для хранения актуального значения `playerShotTargets`:
```typescript
const playerShotTargetsRef = useRef<{ shipId: number; targetShipId: number }[]>([]);

const setPlayerShotTargetsWithRef = (targets) => {
  playerShotTargetsRef.current = targets;
  setPlayerShotTargets(targets);
};
```

Теперь `executePhase` использует `playerShotTargetsRef.current` вместо `playerShotTargets` из замыкания.

Доработка стратегической карты (Гексагональная сетка и координаты)
Дата: [18.10.2026]

В ходе работы над стратегической картой была полностью переработана логика отрисовки гексагональной сетки и определения координат под курсором мыши. Это позволило добиться идеального визуального совпадения сетки с картой Тихого океана и точного позиционирования.

1. Идеальная привязка и отрисовка сетки
Возврат к оригинальной привязке: Сетка была возвращена к своему первоначальному визуальному положению относительно карты (без смещений по X и Y). Это критически важно, так как все города, базы и корабли (например, Перл-Харбор, Токио) были изначально визуально привязаны к этой сетке.

Размеры гекса: Ширина 21px, высота 25px. Шаг по вертикали (spacing Y) — 18.75px (25 * 0.75). Нечётные ряды смещаются вправо на половину ширины гекса (10.5px).

Отключение программной сетки: Удален/закомментирован блок программной отрисовки гексов (эллипсов), который использовался как fallback. Теперь карта всегда использует загружаемый образец гекса (PNG).

2. Отладка: Вывод координат прямо на карте
В цикл отрисовки гексов добавлен вывод текстовых координат (row, col) красным цветом прямо в центр каждого гекса.

Шрифт был уменьшен (базовый размер 8px, максимум 10px) и убран bold, чтобы цифры аккуратно помещались внутри границ гекса при любом масштабе (зуме).

3. Точное определение координат под курсором (Pixel-to-Hex)
Функция getHexAtPosition была переписана с использованием алгоритма поиска ближайшего центра.

Как это работает: При наведении мыши математика сначала определяет приблизительный гекс. Затем алгоритм проверяет текущий гекс и 6 его соседей (сверху, снизу, слева, справа и по диагоналям). Вычисляется расстояние от курсора до центров всех 7 гексов, и выбирается тот, чей центр оказался ближе всего.

Результат: Координаты в верхней панели теперь всегда на 100% совпадают с красными цифрами на карте, даже если наводить мышь на самый край или угол гекса (раньше в углах координаты «прыгали» на соседние ряды).

4. Интерфейс и UX
Координаты гекса под курсором (например, Гекс: 5,10) выводятся в верхней панели в моноширинном шрифте (Cyan цвет) рядом с заголовком.

При выходе курсора за пределы карты отображение координат скрывается.

Разработка Картографа (Редактора гексов)
Дата: [20.10.2026]

В ходе работы над стратегической картой был создан и значительно доработан Картограф — специализированный редактор для назначения типа местности и настройки сторон (границ) каждого гекса. Это ключевой этап для перехода от простой картинки к полноценной симуляции варгейма.

1. Базовая функциональность Картографа
Типы местности: реализована поддержка 33 типов ландшафта (равнина, горы, джунгли, города, ЖД, реки и т.д.). Каждому типу присвоен свой цвет и краткое буквенное обозначение (например, «Р» — равнина, «ПП» — пустыня+пески).

Отрисовка на карте: выбранный тип местности отображается на карте в виде цветной заливки гекса и буквенной аббревиатуры в его центре.

Редактор сторон: реализована панель справа, где можно настраивать 6 сторон гекса (NW, NE, W, E, SW, SE). Для каждой стороны доступны 6 кнопок:

🌊 Побережье

🛤️ Главная ЖД

🚂 Второстепенная ЖД

🛣️ Автодорога

⛰️ Грунтовка

🚫 Запрет движения

Взаимоисключение дорог: на одной стороне не могут одновременно находиться разные типы дорог (установка ЖД убирает грунтовку и т.д.).

2. Визуализация в редакторе
Справа отображается увеличенный гекс (Pointy-top), на котором визуально отображаются все изменения:

Побережье — яркая толстая синяя линия по грани гекса.

Запрет — яркая толстая красная линия по грани.

Дороги и ЖД — линии, сходящиеся от граней к центру гекса (в центр, к значку местности). ЖД имеет черную основу с белыми «шпалами».

В центре увеличенного гекса отображается аббревиатура и название выбранного типа местности.

3. Интерфейс и Управление
Инструменты: кисти «Ландшафт» и «Стереть», а также кликабельная легенда для быстрого выбора типа местности.

Масштабирование: только два положения (100% и 200%), с сохранением центра карты при переключении.

Навигация по карте: перетаскивание мышью, колесо мыши для зума (только 100% и 200%).

Навигация по гексам с клавиатуры: выделенный гекс можно перемещать на соседние с помощью стрелок (← ↑ → ↓). Учтено смещение нечетных рядов гексагональной сетки.

Отладка: кнопка «Показать координаты» (выводит красные индексы row,col на каждом гексе).

4. Оптимизация хранения (Критически важное изменение)
Переход на IndexedDB: из-за лимита памяти браузера (5 МБ), при котором происходили вылеты страницы при редактировании соседних гексов, было принято решение перевести хранение данных из localStorage в IndexedDB.

Миграция данных: добавлена кнопка «📥 Импорт из localStorage», которая позволяет перенести ранее созданные гексы в новую базу данных без потери прогресса. Все изменения теперь сохраняются асинхронно, что полностью исключает вылеты браузера.

Защита данных: добавлена проверка структуры гексов (если данные повреждены или отсутствуют поля — они создаются заново), что исключает «белый экран» при редактировании.

5. Статус готовности гексов
Добавлена кнопка «✔️ Готовый гекс». При её нажатии гекс помечается как полностью отредактированный.

Готовые гексы на карте выделяются красным контуром. Выбранный гекс выделяется желтым контуром. Это позволяет визуально контролировать прогресс создания карты.
